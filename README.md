# 青知法苑——基于游戏化学习的青少年普法平台

> 像打游戏一样学法律 —— 面向中学生的游戏化普法教育平台

---

## 一、作品简介

### 1.1 项目背景

随着互联网的普及，青少年接触法律问题的场景日益增多：校园欺凌、网络诈骗、个人信息泄露、消费维权、交通安全、毒品诱惑等问题层出不穷。然而，传统的普法教育方式往往以枯燥的法律条文为主，难以吸引青少年的注意力，学习效果有限。

本项目旨在通过**游戏化学习（Gamification）**的方式，将法律知识融入闯关挑战、漫画阅读、AI 对话等互动形式中，让初中生在"玩中学、学中玩"，培养基本的法律素养和自我保护意识。

### 1.2 核心功能

平台设有**学生端**和**教师端**两个角色，功能如下：

#### 学生端

| 功能模块 | 说明 |
|---------|------|
| **学习闯关** | 6 大法律主题、28 个关卡，每关包含多道情境化选择题、判断题和案例分析题，答对获得经验值，按顺序解锁 |
| **漫画学法** | 3 套基于真实案例改编的普法漫画（校园欺凌、网络诈骗、消费者权益），阅读完毕获得经验值奖励 |
| **AI 普法助手** | 基于扣子（Coze）智能体平台，学生可以自由提问法律问题，获得适合未成年人阅读的法律建议和行动指南 |
| **资源中心** | 浏览法律案例、法律条文摘要、视频、文章等多种类型的普法资源，支持关键词搜索 |
| **任务中心** | 查看教师布置的关卡任务和资源阅读任务，完成后提交 |
| **成长中心** | 个人学习数据仪表盘，包含等级系统、经验值进度、9 枚成就徽章、连续学习天数、每周学习趋势图表 |

#### 教师端

| 功能模块 | 说明 |
|---------|------|
| **进度看板** | 查看班级整体数据：学生人数、近7日活跃人数、挑战总次数、平均得分 |
| **班级管理** | 创建班级、生成邀请码、查看班级成员及个人学习数据（答题次数、平均分、完成关卡数） |
| **任务布置** | 向班级布置关卡挑战或资源阅读任务，设置截止日期 |
| **资源发布** | 教师可发布法律案例、法律摘要、视频、文章等普法资源供学生浏览 |

### 1.3 学习内容覆盖

平台的学习内容涵盖青少年日常生活中最常见的 6 大法律主题：

1. **校园安全** —— 校园欺凌的识别与应对、受教育权保护
2. **网络安全** —— 网络诈骗防范、个人信息保护、网络言论边界
3. **家庭权益** —— 未成年人家庭保护、家庭暴力的识别
4. **消费维权** —— 网购维权、消费者权利、预付卡退款
5. **交通安全** —— 交通法规、骑行安全、事故处理
6. **禁毒教育** —— 毒品危害认知、识别与拒绝技巧

每个主题下设 4-6 个关卡（共 28 个关卡），每个关卡包含 3-10 道题目，题目类型包括：
- **单选题（SINGLE）**：标准四选一
- **判断题（TRUE_FALSE）**：判断对错
- **情境题（SCENARIO）**：基于真实场景的案例分析

所有题目均配有详细解析，答错后可查看正确答案与法律依据。

### 1.4 游戏化设计

- **经验值系统（XP）**：答对关卡（得分 ≥ 60）获得对应经验值奖励，阅读漫画获得 10 XP
- **等级系统**：每积累 100 XP 升一级，等级对应不同的称号（法律小白 → 初级法律达人 → 法律知识进阶 → 法律小专家 → 法律小达人）
- **成就徽章**：9 枚可解锁的成就徽章，涵盖学习起步、连续打卡、高分挑战、关卡通关等多个维度
- **顺序解锁**：每个主题内的关卡需按顺序完成，完成后才能解锁下一关
- **错题复习**：得分低于 100 分的关卡会进入"待复习"列表，鼓励学生巩固薄弱环节
- **每日优先任务**：成长中心会根据学生当前进度智能推荐下一个学习目标

### 3.2 Docker 部署（推荐）

**第一步：克隆项目**

```bash
git clone <仓库地址>
cd legal_for_teenager
```

**第二步：配置环境变量**

复制环境变量模板并根据需要修改：

```bash
cp .env.example .env
```

主要配置项：

```env
# MySQL
MYSQL_ROOT_PASSWORD=root123
MYSQL_DATABASE=lft_db
MYSQL_USER=lft_user
MYSQL_PASSWORD=lft_pass123

# JWT
JWT_SECRET=替换为一个随机字符串
JWT_EXPIRES_IN=7d

# CORS
FRONTEND_ORIGIN=http://localhost

# AI（可选，不配置则使用默认回复）
OPENAI_API_KEY=你的API密钥
OPENAI_MODEL=deepseek-v4-flash
```

**第三步：启动全部服务**

```bash
docker compose -p lft up -d
```

首次启动会自动构建镜像并初始化数据库，约需 3-5 分钟。

**第四步：初始化种子数据（可选）**

```bash

```

**第五步：访问**

| 服务 | 地址 |
|------|------|
| 前端页面 | http://localhost |
| 后端健康检查 | http://localhost:3001/api/health |

**种子账号：**

| 角色 | 邮箱 | 密码 |
|------|------|------|
| 学生 | student@example.com | Student123! |
| 教师 | teacher@example.com | Teacher123! |

```bash
# 查看日志
docker compose -p lft logs -f

# 停止服务
docker compose -p lft down

# 重新构建（代码更新后）
docker compose -p lft build
```

### 3.3 本地开发安装（无 Docker）

**第一步：克隆项目并安装依赖**

```bash
git clone <仓库地址>
cd legal_for_teenager

# 分别安装前后端依赖
cd frontend && npm install
cd ../backend && npm install
```

**第二步：配置后端环境变量**

创建 `backend/.env`：

```env
DATABASE_URL="mysql://root:密码@localhost:3306/lft_db"
JWT_SECRET="一个随机的长字符串"
FRONTEND_ORIGIN="http://localhost:5173"
```

**第三步：创建数据库并初始化**

```sql
CREATE DATABASE lft_db DEFAULT CHARACTER SET utf8mb4;
```

```bash
cd backend
npx prisma generate
npx prisma migrate deploy
npx prisma db seed
```

**第四步：启动开发服务器**

在两个终端中分别运行：

```bash
# 终端 1：启动后端（端口 3001）
cd backend
npm run dev

# 终端 2：启动前端（端口 5173）
cd frontend
npm run dev
```

前端访问 `http://localhost:5173`，后端 API 运行在 `http://localhost:3001`。开发模式下 Vite 自动将 `/api` 请求代理到后端。

## 四、设计思路

### 4.1 整体架构

项目采用**前后端分离架构**，通过 Docker 容器化部署：

- **前端**：基于 React 的单页应用（SPA），通过 Vite 构建，Tailwind CSS 实现响应式设计。生产环境由 Nginx 提供静态文件服务和 SPA fallback
- **后端**：基于 Express.js 的 RESTful API，提供 JSON 接口，通过 Prisma ORM 操作 MySQL 数据库
- **数据库**：MySQL 8.x，由 Docker 独立容器运行
- **部署**：Docker Compose 编排三个容器，Nginx 反向代理 `/api` 请求到后端，实现同源访问

```
                           ┌─────────────────┐
                           │   浏览器访问     │
                           │  http://localhost │
                           └────────┬────────┘
                                    │
                           ┌────────▼────────┐
                           │   frontend       │
                           │   (Nginx:80)     │
                           │                  │
                           │  / → index.html  │
                           │  /api/* → proxy  │
                           └────────┬────────┘
                                    │
                           ┌────────▼────────┐
                           │   backend        │
                           │  (Express:3001)  │
                           │   RESTful API    │
                           └────────┬────────┘
                                    │
                           ┌────────▼────────┐
                           │   MySQL 8.x      │
                           │   (db:3306)      │
                           └─────────────────┘
```

开发模式下，Vite 开发服务器（端口 5173）通过 `vite.config.ts` 中配置的 proxy 将 `/api` 请求转发到后端（端口 3001），无需跨域配置。

### 4.2 用户角色与权限设计

系统设计了两个核心角色——**学生**和**教师**，通过 JWT Token 进行身份认证，通过中间件实现路由级别的权限控制：

- `requireAuth`：验证请求是否携带有效 JWT Token，未认证返回 401
- `requireRole`：验证用户角色是否匹配（如教师专属 API 需要教师角色）

前端路由同样配置了认证守卫，未登录用户自动跳转到登录页，学生无法访问教师路由，反之亦然。

### 4.3 游戏化学习模型

平台的核心设计理念是**将法律学习游戏化**，具体体现在以下机制：

**经验值（XP）与等级系统**
- 每完成一个关卡且得分 ≥ 60 分，获得该关卡设定的 XP 奖励（默认 10 XP）
- 每阅读一篇漫画获得 10 XP
- 每 100 XP 升一级，等级映射为不同的法律称号，营造成就感

**顺序解锁机制**
- 每个法律主题内的关卡按顺序排列
- 只有当前关卡完成后，下一关才会解锁
- 已完成的关卡显示最佳成绩，支持重复挑战刷新记录
- 这一机制避免了学生跳过基础内容，确保知识体系的完整性

**成就徽章系统**
- 设计了 9 枚成就徽章，覆盖学习起步、连续打卡、高分挑战、关卡通关等多个维度
- 成就分为"已解锁""进行中""即将解锁"三种状态
- 解锁时有庆祝动画效果，增强正反馈

**错题复习机制**
- 得分低于 100 分的关卡自动进入"待复习"列表
- 成长中心的"每日优先任务"会智能推荐下一个学习目标
- 鼓励学生反复练习，巩固薄弱环节

### 4.4 内容设计思路

**6 大法律主题的选择依据**：基于《中华人民共和国未成年人保护法》《预防未成年人犯罪法》等法律法规，结合青少年日常生活中最常遇到的法律场景进行筛选。

**题目设计原则**：
- 所有题目基于真实法律条文和真实案例改编
- 题目语言适合初中生阅读理解水平
- 情境题模拟真实场景，培养学生的法律应用能力
- 每道题配有详细解析，答错后可查看正确答案与法律依据

**漫画内容**：
- 3 套漫画分别对应校园欺凌、网络诈骗、消费者权益三个高频场景
- 每套 6 格漫画讲述一个完整故事
- 阅读完毕后展示"法律小课堂"页面，包含法律贴士和相关法条引用

### 4.5 AI 普法助手设计

AI 助手是平台的特色功能，基于**扣子（Coze）智能体平台**构建，设计思路如下：

- **智能体驱动**：在扣子平台上预配置"青少年普法小助手"智能体，通过 Web SDK 嵌入前端页面，实现对话式交互
- **安全的对话边界**：智能体提示词明确要求 AI 不提供具体法律意见，只做学习解释与一般性建议
- **高风险内容识别**：遇到自伤、暴力、性侵、勒索等内容，优先建议立即求助监护人/老师/报警
- **适合未成年人阅读**：语言温和、不使用恐吓或刺激性描述
- **行动导向**：尽量给出 3-5 条可操作的行动清单
- **即开即用**：无需额外配置 API 密钥，前端页面加载后即可使用，降低部署门槛

### 4.6 UI/UX 设计思路

**视觉风格**：
- 采用清新的蓝绿色调为主色，搭配白色卡片和浅灰背景
- 大量使用圆角（rounded-xl/2xl）和毛玻璃效果（backdrop-blur），营造现代感和亲和力
- 渐变色用于强调按钮和关键信息，避免过于花哨

**响应式设计**：
- 桌面端：左侧固定侧边栏导航 + 右侧内容区
- 移动端：顶部导航栏 + 底部弹出抽屉菜单，适配手机和平板
- 漫画阅读器支持触摸滑动翻页

**深色/浅色主题**：
- 支持一键切换深色/浅色主题
- 自动检测系统偏好设置
- 主题选择持久化到 localStorage

**交互反馈**：
- Toast 通知系统用于操作反馈（如 XP 获得、任务提交成功等）
- 加载状态使用骨架屏（Skeleton）动画
- 空状态提供引导提示
- 按钮点击有明确的视觉反馈

## 五、设计重点与难点

### 5.1 重点一：游戏化闯关系统的状态管理

**难点描述**

闯关系统涉及复杂的状态流转：关卡的解锁/锁定状态、答题进度、最佳成绩、经验值计算、等级晋升等。这些状态分布在前后端，需要保持一致性。

**解决方案**

- 后端通过 `UserProgress` 模型记录每个学生对每个关卡的最佳成绩和完成状态
- 前端通过 Zustand 管理用户的全局信息（XP、等级），闯关完成后通过回调更新
- 顺序解锁逻辑在后端实现：API 返回的关卡列表中，每个关卡带有 `progress` 字段，前端根据 `bestScore > 0` 判断是否完成，根据关卡顺序判断是否解锁
- 答题过程完全在前端完成（模态框内），提交时一次性将所有答案发送到后端校验

### 5.2 重点二：漫画阅读器的交互设计

**难点描述**

漫画阅读器需要同时支持桌面端和移动端，提供流畅的翻页体验，并且在阅读完成后触发经验值奖励。

**解决方案**

- 使用全屏模态框覆盖层实现沉浸式阅读体验
- 桌面端支持键盘左右箭头翻页，移动端支持触摸滑动手势翻页（50px 阈值判断方向）
- 底部进度点指示当前位置，已阅读页显示实心圆点
- 最后一页后自动追加"法律小课堂"页面，包含法律贴士和法条引用
- 到达法律小课堂页面时，调用 API 标记阅读完成并发放 XP 奖励
- XP 获得时播放 2 秒的庆祝动画（撒花 emoji + 经验值数字弹出）
- 幂等性保证：已阅读的漫画不会重复发放 XP，前端通过已读集合做前置判断

### 5.3 重点三：AI 助手的安全性设计

**难点描述**

AI 助手面向未成年人，必须确保对话内容的安全性，同时提供有价值的法律学习建议。

**解决方案**

- 在扣子平台配置智能体时，精心设计系统提示词（System Prompt），明确以下约束：
  - 不提供具体法律意见或办案结论
  - 遇到高风险内容（自伤、暴力、性侵、勒索）优先建议求助
  - 内容适合未成年人阅读，不使用恐吓性描述
  - 给出 3-5 条行动清单而非模糊建议
- 前端页面提供快捷提问模板，引导学生围绕常见法律场景提问
- 使用边界说明卡片明确告知学生 AI 助手的局限性，并提供 110、12348 等求助热线

### 5.4 重点四：前后端认证与权限体系

**难点描述**

系统有学生和教师两个角色，需要严格的路由权限控制，防止越权访问。

**解决方案**

- 后端使用 JWT Token 认证，Token 中包含用户 ID 和角色信息
- `requireAuth` 中间件拦截未认证请求，`requireRole` 中间件校验角色权限
- 前端路由使用 `RequireAuth` 组件包裹，启动时通过 `bootstrap()` 从 Token 恢复用户状态
- 教师专属 API（如创建班级、布置任务）在后端强制校验教师角色
- 学生加入班级通过邀请码机制，教师无法直接将学生加入班级

### 5.5 重点五：教师看板的数据聚合

**难点描述**

教师看板需要实时展示班级整体数据（活跃人数、平均得分等），涉及跨表聚合查询。

**解决方案**

- 使用 Prisma 的聚合查询功能（`_count`、`_avg` 等）在数据库层面完成计算
- 活跃学生统计基于最近 7 天内有答题记录的学生去重计数
- 平均得分基于所有答题记录的 `score` 字段计算
- 按班级维度过滤数据，确保教师只能查看自己班级的信息

### 5.6 重点六：Windows/Linux 跨平台兼容

**难点描述**

项目在 Windows 环境开发，部署到 Linux 服务器时，MySQL 在 Linux 上默认区分表名大小写，导致数据库迁移失败。

**解决方案**

- 统一迁移 SQL 文件中的表名大小写，与 `CREATE TABLE` 语句保持一致
- 确保 Prisma 生成的迁移文件在两个平台上都能正确执行
- `.gitignore` 中精确指定忽略的 `.env` 文件，避免误忽略 `.env.example`

## 六、创新描述

### 6.1 游戏化普法教育模式

传统的青少年普法教育多以课堂讲授、发放宣传册为主，形式单一，学生参与度低。本项目创新性地将法律知识学习融入**游戏化闯关系统**，通过经验值、等级、徽章、顺序解锁等游戏机制，将枯燥的法律条文转化为有趣的挑战任务。学生不再是被动接受知识，而是主动探索、挑战、通关，在游戏中自然地掌握法律常识。

### 6.2 情境化题目设计

区别于简单的法条记忆题，本项目的题目大量采用**情境化设计（SCENARIO 类型）**。每道情境题模拟一个真实的生活场景（如"同学在群里发布你的照片并配侮辱性文字，你应该怎么做？"），要求学生运用法律知识进行分析和判断。这种设计不仅考察学生对法律条文的记忆，更培养了他们在真实场景中运用法律保护自己的能力。

### 6.3 漫画 + 法律课堂的融合

本项目创新性地将**普法漫画与法律课堂相结合**。每套漫画讲述一个完整的法律故事（如校园欺凌、网络诈骗），阅读完毕后自动展示"法律小课堂"页面，包含实用的法律贴士和具体法条引用。这种"故事引入 → 知识强化"的模式，既保持了阅读的趣味性，又确保了法律知识的准确传达。

### 6.4 扣子智能体驱动的普法助手

平台集成了基于**扣子（Coze）智能体平台**的 AI 普法助手。后端通过 OpenAI 兼容接口调用扣子部署的模型（支持 DeepSeek 等多种模型），学生可以在全屏聊天界面中随时提问。AI 助手具备以下创新特点：
- **智能体架构**：利用扣子平台预配置的专业普法智能体，后端通过 OpenAI 兼容接口调用，支持 DeepSeek、GPT 等多种模型热切换
- **未成年人适配**：系统提示词专门针对未成年人场景优化，语言温和易懂，不提供具体法律意见
- **安全边界**：遇到高风险场景（自伤、暴力、性侵、勒索）自动引导求助，避免不当建议
- **便捷交互**：全屏聊天界面，支持 Markdown 渲染、快捷提问模板、实时打字指示器，交互体验流畅自然

### 6.5 双角色协同教学设计

平台同时服务学生和教师两个角色，形成**教学闭环**：
- 教师可以创建班级、发布任务、监控学习进度
- 学生在闯关、漫画、AI 对话中自主学习
- 教师通过看板实时了解班级整体学习情况和个人表现
- 任务系统将教师的引导与学生的自主学习有机结合

这种设计将传统的"教师讲、学生听"模式，转变为"学生自主探索 + 教师精准引导"的新型普法教育模式。

### 6.6 成长中心的数据可视化

成长中心将学生的学习数据以**可视化仪表盘**的形式呈现，包含：
- 等级与经验值进度条
- 9 枚成就徽章的解锁进度
- 7 日学习趋势柱状图
- 连续学习天数与每周目标追踪
- 基于学习数据的个性化下一步建议

通过数据可视化，学生可以直观地了解自己的学习进度，教师也可以快速评估教学效果。这种"数据驱动学习"的方式在青少年普法教育领域具有创新意义。

### 6.7 全栈 TypeScript 类型安全

项目从前端到后端全面采用 TypeScript，并通过 Prisma ORM 实现数据库操作的类型安全。这种全栈类型安全的架构保证了：
- 前后端接口类型一致，减少联调错误
- 数据库查询结果类型明确，避免运行时类型错误
- 重构时编译器自动检测破坏性变更，提高代码可维护性

在学生竞赛/MVP 项目的规模下采用这种工程化实践，体现了对代码质量的重视。
